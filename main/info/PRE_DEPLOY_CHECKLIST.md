# 건설기업 재무분석 서비스 — 배포 전 개발 체크리스트

## 목표와 범위

- 화면은 Streamlit으로 구현하고, 로컬 검증을 마친 뒤 Render에 배포한다.
- 이 문서의 범위는 **배포할 준비가 된 로컬 프로토타입 완성까지**다. 실제 Render 서비스 생성은 다음 작업으로 진행한다.
- 사용자: 건설업종 종목 2~3개를 보유하고, 연말 실적 발표 전에 보유 기업의 재무상태를 비교하고 내년 수익성을 가늠하려는 개인 투자자.
- 시연 흐름: 기업 선택 → 재무현황 확인 → 기업 간 비교 → 차년도 영업이익률 예상값 확인.
- 1단계 예측은 최근 3년 영업이익률 평균을 사용하는 규칙 기반 방식으로 구현한다.
- 사용할 CSV와 열 이름은 MUST 기능 명세를 확정한 다음 결정한다.

- [ ] 이번 단계 제외 목록을 적는다: 로그인, 실시간 DART 조회, 뉴스 분석, 매매 추천, ML 모델 학습, REST API 구현.

완료 기준: 사용자, MUST 3개, 완료 조건, 개발 순서, 예상 시간, 제외 범위가 문서에 있다.

## 4. US-3 — 규칙 기반 예측부터 완성

순서: **core.py 예측 함수 → pytest → 폼 → 결과**.

- [ ] 기업과 기준 연도를 받아 최근 3년 영업이익률 평균을 계산하는 함수를 작성한다.
- [ ] 기준 연도가 T라면 T-2, T-1, T의 연속된 3개년 값만 사용한다.
- [ ] 기준 연도 이후 데이터가 계산에 포함되지 않게 한다.
- [ ] 3개년 중 누락된 연도나 값이 있으면 예측 불가 사유를 반환한다.
- [ ] 정상 평균 계산, 3개년 자료 부족, 미래 데이터 제외를 pytest로 검증한다.
- [ ] 기업·기준 연도 선택과 예측 버튼을 폼으로 구현한다.
- [ ] 예상 영업이익률(%), 예측 대상 연도(T+1), 사용한 3개년 값과 계산 방식을 표시한다.
- [ ] 결과에 '최근 3년 평균 기반 예상값'이라고 명시한다.
- [ ] 결과를 세션 상태에 저장하고, 선택 조건 변경 시 과거 결과가 현재 결과로 오인되지 않도록 처리한다.
- [ ] 자료 부족 시 오류 대신 안내가 표시되는지 확인한다.
- [ ] 실행 확인 후 `US-3:`으로 시작하는 메시지로 커밋하고 AI 활용 기록을 남긴다.

완료 기준: 실제 CSV를 이용해 기업 선택부터 예상값 확인까지 작동한다.

## 5. US-1 — 재무현황 조회

순서: **CSV 로드(캐시) → 기업 선택 → 지표 → 차트**.

- [ ] 기업과 조회 연도를 선택하도록 구성한다.
- [ ] 선택 기업·연도의 매출액, 영업이익률, 부채비율을 표시한다.
- [ ] 기업별 영업이익률 추이 차트를 하나 표시하고 연도순으로 정렬한다.
- [ ] 금액 단위와 비율 단위를 화면에 표시한다.
- [ ] 없는 연도를 선택할 수 없도록 하거나, 조회 결과가 없으면 안내한다.
- [ ] 지표 일부가 누락되어도 나머지 지표는 표시한다.
- [ ] 기업·연도 변경 시 지표와 차트가 갱신되는지 확인한다.
- [ ] 실행 확인 후 `US-1:` 커밋과 AI 활용 기록을 남긴다.

완료 기준: 기업별 주요 지표와 추이 하나를 오류 없이 확인할 수 있다.

## 6. US-2 — 기업 간 비교

순서: **CSV 로드(캐시) → 비교 기업 선택 → 지표 → 차트**.

- [ ] 기업 2~3개와 비교 연도를 선택하도록 구성한다.
- [ ] 같은 연도의 영업이익률·부채비율·유동비율 비교표를 표시한다.
- [ ] 세 지표 중 하나를 선택해 기업별 비교 차트로 표시한다.
- [ ] 기업이 2개 미만이거나 공통 연도가 없으면 안내한다.
- [ ] 누락된 지표는 '자료 없음'으로 표시하고, 차트에서 0으로 대체하지 않는다.
- [ ] 기업·연도·지표를 바꾸면 표와 차트가 갱신되는지 확인한다.
- [ ] 실행 확인 후 `US-2:` 커밋과 AI 활용 기록을 남긴다.

완료 기준: 기업 2~3개의 동일 연도 지표 3개를 비교할 수 있다.

## 7. 전체 흐름과 예외 상황 검증

- [ ] 위젯 변경 후 예측 결과가 사라지거나 다른 기업의 결과로 잘못 표시되지 않는지 확인한다.
- [ ] 기준 연도와 예측 대상 연도가 화면에서 명확히 구분되는지 확인한다.

- [ ] 피드백을 '현재 되는 것 / 반드시 고칠 것 / 줄일 것' 세 항목으로 기록한다.
- [ ] 필수 오류를 수정한 뒤 영향을 받는 기능과 전체 시연 흐름을 다시 확인한다.

완료 기준: MUST 기능 모두 정상 동작하고 빈 결과에서도 앱이 중단되지 않는다.

## 이후 단계에 남길 사항

- 2단계: 회귀 모델 학습 및 규칙 기반 예측과의 성능 비교.
